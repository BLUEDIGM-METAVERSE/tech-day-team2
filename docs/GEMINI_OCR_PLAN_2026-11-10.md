## 목표와 처리 흐름

마스킹한 실제 영수증을 선택하면 사용자가 사진을 확인한 뒤 **영수증 읽기**를 누른다. 서버가 Gemini에서 줄 단위 텍스트를 얻고 기존 파서로 일자·거래처·금액을 추출한다. 사용자는 사진과 추출값을 대조해 수정하고, 확인한 행을 기존 목록에 추가해 엑셀로 복사한다.

### 1. Google AI Studio 프로젝트와 서버 설정

- 팀의 비용 0원 원칙에 맞춰 무료 할당량이 있는 프로젝트에서 테스트한다. [Google AI Studio API 키 화면](https://aistudio.google.com/apikey)에서 해당 프로젝트를 선택하고 새 인증 키를 발급한다. 이미지 입력과 구조화 출력을 지원하며 프로젝트 무료 할당량으로 호출 가능한 Flash 계열 모델을 샘플 호출로 확인한다. [키 설정](https://ai.google.dev/gemini-api/docs/api-key) · [가격](https://ai.google.dev/gemini-api/docs/pricing) · [요청 한도](https://ai.google.dev/gemini-api/docs/rate-limits)
- 서버 환경변수로 `OCR_MODE=gemini`, `GEMINI_API_KEY`, `GEMINI_MODEL`을 전달한다. 예시 설정에는 이름과 빈 값만 둔다. 실제 키는 로컬 환경 또는 Git에서 제외되고 서버만 읽는 환경 파일에 둔다. 브라우저 환경변수와 로그에는 키를 넣지 않는다.
- 기본 모드는 기존 `mock`으로 두고 명시적으로 선택한 경우에만 Gemini를 시작한다. Gemini 모드에서 설정이 빠지면 서버 시작 시 누락된 변수 이름만 안내한다. `/api/health`로 설정된 모드를 확인하고, 키 권한과 모델 호출 가능 여부는 가짜 영수증으로 별도 확인한다.

### 2. 마스킹과 이미지 전송

- 첫 구현은 사전에 마스킹한 파일을 로컬 PC에서 선택하는 흐름으로 검증한다. 마스킹한 이미지를 미리보기에서 확인한 뒤에만 전송한다. 인앱 마스킹은 별도 범위로 두고, QR로 받은 이미지는 동일한 마스킹 절차가 마련된 뒤 Gemini 전송에 연결한다.
- 카드·승인번호, 전화번호, 주소, 회원·주문 식별자와 사내 기밀을 포함해 팀이 정한 가림 항목을 이미지 픽셀에 적용한다. 추출 대상인 일자·거래처·최종 금액도 민감하거나 기밀이면 해당 영수증을 외부 실험에서 제외한다. Google은 무료 서비스에 민감·기밀·개인정보를 제출하지 말도록 안내한다. 가림 확인 UI는 사용자의 확인 절차이며 이미지의 개인정보 유무를 자동 판별하지 않는다. [Gemini API 이용약관](https://ai.google.dev/gemini-api/terms?authuser=00)
- `frontend/src/services/extract.ts`와 `backend/src/app.mjs`를 연결한다. 초안은 Gemini 모드의 `POST /api/extract`에 이미지 바이트를 전송하고 JPEG·PNG·WebP만 허용하는 방식이다. 본문 상한은 8MiB를 초기 후보로 두며, 실제 축소본 크기를 보고 확정한다. 서버는 빈 본문, 크기 초과, MIME과 파일 시그니처 불일치를 Gemini 호출 전에 거부한다. 샘플 모드는 기존 본문 없는 요청을 유지한다.
- 기본 접속은 로컬로 제한한다. 영수증 이미지와 OCR 원문은 처리 중 메모리에서만 다루고 로그·파일·브라우저 저장소에 남기지 않는다. Google에 보낼 때는 이미지 인라인 입력을 사용한다. [Gemini 이미지 입력](https://ai.google.dev/gemini-api/docs/image-understanding)

### 3. OCR 및 후처리

- `backend/src/ocr/`에 서버 전용 Gemini 어댑터를 추가해 기존 엔진 주입 지점을 사용한다. 이미지의 글자를 줄 순서와 라벨을 유지해 옮기도록 요청하고, `{text: string}` 응답을 구조화 출력과 서버 검증으로 받는다. 잘린 글자나 읽기 어려운 숫자는 보완해서 쓰지 않도록 지시한다. 이미지 속 문구는 판독 대상으로만 취급한다. [Gemini 구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output)
- `parseReceiptText()`로 거래일을 `YYYY-MM-DD`, 금액을 원 단위 양의 정수로 정규화하고 거래처 표기를 정리한다. 서로 다른 합계가 충돌하거나 취소·환불로 최종 금액이 불명확하면 `null`과 검토 경고를 반환한다. 실제 샘플에서 발견한 OCR 오인식은 기대값과 함께 파서 회귀 테스트로 남긴다.
- API 응답은 기존 `{data:{date,merchant,amount},engine,warnings}`를 유지하고 `engine`에 Gemini를 표시한다. 빈 판독은 누락 경고가 있는 결과로, 잘못된 공급자 응답·키 권한·한도·시간 초과는 각각 안내 가능한 API 오류로 처리한다. 공급자 응답 원문은 화면이나 로그에 노출하지 않는다.
- 서버의 Gemini 호출 제한을 브라우저 요청 제한보다 짧게 두어 서버가 오류 안내를 반환할 시간을 확보한다. 예를 들어 20초/30초로 시작하고 실측 후 확정한다. 취소 신호를 공급자 호출까지 전달하고 자동 재시도 없이 사용자가 사진을 유지한 채 다시 시도하도록 한다.

### 4. 결과 확인 화면

- `App.tsx`와 `UploadPanel.tsx`에서 샘플 모드와 Gemini 모드의 버튼 이름을 구분하고 읽는 동안 중복 요청을 막는다. 이미지 교체·제거 시 이전 요청의 결과나 오류가 새 사진에 표시되지 않도록 한다.
- `ResultPanel.tsx`의 기존 편집 영역에서 사진과 일자·거래처·금액을 비교할 수 있게 한다. 엔진과 필드별 경고를 보여주고 누락값은 빈칸으로 둔다. 날짜·거래처·금액을 확인 또는 수정해 필수값 검증을 통과하면 기존 목록 추가와 6열·원본 양식 복사를 사용한다. 계정과목·결제수단·프로젝트번호 입력 방식은 기존 계약을 따른다.

## 검증과 완료 기준

| 검증 | 확인할 결과 |
| --- | --- |
| 자동 검사 | 기존 검사·빌드·테스트를 통과한다. 가짜 엔진으로 이미지 입력, 빈 파일·형식·용량, 키 권한·429·타임아웃·응답 형식 오류 매핑을 검증한다. 정상 응답과 판독 불가 응답을 구분한다. |
| 실제 Gemini 호출 | 가짜 21장과 사전 마스킹한 실제 영수증 최소 5장으로 검증한다. 카드전표·일반 매장 영수증과 흐림·기울어짐·복수 합계를 포함한다. 사람이 작성한 정답과 필드별 일치·누락·오검출 및 응답 시간을 기록한다. |
| 화면에서 끝까지 | 정상 실제 샘플에서 사진에 해당하는 값과 Gemini 표시를 확인한다. 누락값 수정 → 목록 추가 → 6열 및 B~X 양식 사본에 붙여넣기까지 확인한다. 이미지 교체와 오류 후 재시도도 시험한다. |
| 판독 품질 | 정상 샘플별 실제값과 비교하고, 모호한 샘플은 해당 값을 빈칸·경고로 처리하는지 확인한다. 틀린 금액이 경고 없이 표시되면 해당 유형을 회귀 테스트에 추가하고 수정 후 재검증한다. 기록에는 가명 샘플 ID와 집계만 남긴다. |

서버·OCR 담당이 전송 형식, 오류, 무료 사용 범위와 타임아웃을 먼저 합의한다. 업로드·결과 담당이 마스킹 확인과 결과 화면을 연결한다. 구현 뒤 `README.md`, `docs/connection.md`, `docs/decisions.md`와 AI 활용 기록을 갱신하고 팀원 1명 리뷰를 받는다. 이 계획의 모델, 용량, 타임아웃은 제안이며 실제 호출 결과를 보고 확정한다.
