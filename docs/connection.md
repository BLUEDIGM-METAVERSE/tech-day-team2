# API·데이터 계약

기본 주소는 프런트 `127.0.0.1:5173`, API `127.0.0.1:3001`이다. 프런트는 `/api`를 호출하고 Vite 프록시가 API 서버로 전달한다.

## 샘플 추출

- `GET /api/health` → `200 {status:"ok",mode:"mock"}`. `mode`는 서버에 연결된 엔진을 따른다.
- `POST /api/extract` → 요청 본문 없이 고정 샘플을 반환한다. 이미지를 전송하거나 OCR을 수행하지 않는다.
- 응답: `{data:{date:string|null,merchant:string|null,amount:number|null},engine:string,warnings:string[]}`.
- 날짜는 `YYYY-MM-DD`, 금액은 원 단위 정수다. 누락값은 `null`이며 금액을 0으로 대체하지 않는다.

## Gemini 추출

- `GET /api/health`는 Gemini 모드에서 `{status:"ok",mode:"gemini"}`를 반환한다. 키 유효성은 실제 추출 요청에서 확인한다.
- `POST /api/extract`에 최대 8 MiB의 바이너리 이미지와 `Content-Type: image/jpeg|image/png|image/webp` 헤더를 보낸다. PC 파일과 QR 중계 사진은 PC에서 같은 수동 마스킹 화면을 거친다. 사용자가 확인하면 브라우저가 가린 픽셀을 반영한 PNG를 생성해 이 API에 전송한다. QR 중계에는 편집 전 사진이 사용된다.
- 백엔드는 Gemini에 PC가 생성한 PNG를 Base64 인라인 데이터로 보낸다. 요청에는 이미지 MIME 유형, 판독 지시, JSON 응답 스키마가 포함된다. 인증 키는 요청 헤더에, 모델 ID는 API 경로에 들어간다. 서버는 사용자가 가릴 영역을 자동으로 판별하지 않는다.
- Gemini에 카드사·카드번호·승인번호·가맹점번호·매입사명과 거래처 주소·사업자번호·전화번호를 OCR 응답에서 제외하도록 지시한다. 응답에 남은 항목은 백엔드가 인식 가능한 라벨과 번호 형식을 기준으로 후보에서 제거한다. 상호 라벨이 없으면 이미지에서 명확한 이름을 상호로 전사하도록 요청하고, 거래일과 결제금액이 확인된 경우 상단의 단일 상호 후보를 보조 규칙으로 사용한다.
- 일자·거래처·금액 정규화는 로컬 백엔드에서 한 번 수행한다. OCR 원문, 정제 결과, 화면 편집값을 Gemini에 다시 전송하지 않는다. 화면에는 기존 결과 계약을 반환하고 서버 콘솔에는 처리 단계, 민감 항목 필터를 거친 판독 텍스트, 정제한 일자·거래처·금액과 경고를 표시한다.
- Gemini 요청 제한은 20초이고 브라우저의 추출 요청 제한은 30초다. 실패한 이미지는 화면에 남으며 사용자가 다시 시도할 수 있다.
- Vite의 LAN 프록시는 바이너리 이미지 요청을 로컬 접속에서만 허용한다.

| 상태 | 코드 | 조건 |
| --- | --- | --- |
| 400 / 413 / 415 | `BAD_IMAGE` | 빈 본문 또는 시그니처 불일치 / 크기 초과 / 지원하지 않는 MIME |
| 403 | `OCR_LOCAL_ONLY` | LAN에서 Gemini 추출 요청 |
| 429 | `OCR_QUOTA` | Gemini 요청 한도 초과 |
| 502 | `OCR_AUTH`, `OCR_MODEL`, `OCR_BAD_RESPONSE`, `OCR_UNAVAILABLE` | 키·권한, 모델, 응답 형식 또는 공급자 통신 오류 |
| 504 | `OCR_TIMEOUT` | Gemini 호출 시간 초과 |

## 공통 오류

오류 응답은 `{error:{code,message}}`이고 `message`는 화면에 그대로 표시할 수 있는 안내문이다.

| 상태 | 코드 | 조건 |
| :-- | :-- | :-- |
| 400 | `BAD_REQUEST` | 해석할 수 없는 요청 주소 |
| 404 | `NOT_FOUND` | 등록되지 않은 경로·메서드 |
| 500 | `INTERNAL_ERROR` | 처리 중 예외(엔진 실패 포함). 예외 내용은 응답에 넣지 않고 로그에는 오류 종류만 남기며 서버는 계속 동작한다 |

중계 전용 오류는 아래 방 API를 따른다.

프런트의 공통 요청 함수는 `frontend/src/services/http.ts`의 `requestJson`이다.

| 상황 | 화면 안내 |
| :-- | :-- |
| 오류 본문이 있는 응답 | 서버의 `message` |
| 네트워크 실패, 오류 본문이 없는 응답 | 통신 실패·서버 실행 상태 확인·재시도 안내. API 서버가 꺼지면 Vite proxy가 본문 없는 500을 돌려주므로 이 경우에 해당한다 |
| 시간 초과 | 응답 지연·재시도 안내. 샘플 추출의 30초는 임시 값이며 중계 요청에는 시간 제한이 없다 |
| 성공 상태지만 JSON이 아니거나 결과 계약과 다름 | 응답 형식 오류·재시도 안내 |

추출에 실패해도 선택한 이미지는 유지되며 같은 버튼으로 다시 시도한다. 폰 연결 준비에 실패하면 PC 화면의 **다시 시도**를 사용한다.

## 폰 → PC 이미지 중계

서버 메모리에 사진을 대기시켰다가 PC로 전달하는 시제품이다. 호출 함수는 `frontend/src/services/relay.ts`에 있다.

### 방 생성과 연결

`POST /api/rooms` → `201`과 다음 필드를 반환한다.

| 필드 | 의미 |
| :-- | :-- |
| `code` | 표시용 6자리 코드 |
| `key` | 방 접근용 32자리 16진수 키 |
| `hosts` | PC의 외부 인터페이스 IPv4 주소 목록 |
| `expiresAt` | 생성 시각 기준 만료 시각. closesAt과 같다. |
| `closesAt` | 생성 후 30분이 되는 종료 시각 |
| `maxLifeMinutes` / `idleMinutes` | 최대 사용 시간 30분 / 이전 클라이언트 호환용 30분 |

시각은 모두 epoch 밀리초다. PC는 `closesAt`으로 남은 시간을 표시한다.

폰 주소는 `<protocol>://<host>:<port>/?room=<code>&key=<key>`다. PC의 QR을 스캔해 접속하며 코드만 입력하는 기능은 없다. 기본 개발 서버(`npm run dev`)는 프런트를 LAN에 열어 폰 접속을 받는다. `npm run dev:local`은 로컬 접속만 허용해 폰에서 열 수 없다([README](../README.md)).

### 방 API

아래 요청은 모두 `?key=<key>`가 필요하다. 코드·키가 틀리거나 방이 만료되면 `404 ROOM_NOT_FOUND`를 반환한다.

| 요청 | 성공 응답 | 용도 |
| :-- | :-- | :-- |
| `GET /api/rooms/:code` | `200 {ok:true,pending,expiresAt,closesAt}` | 연결 확인·대기 수 조회 |
| `DELETE /api/rooms/:code` | `200 {closed:true}` | 방 닫기 |
| `POST /api/rooms/:code/images` | `202 {pending}` | 사진 보내기 |
| `GET /api/rooms/:code/next` | `200 {image,pending,expiresAt,closesAt}` | 다음 사진 가져오기. 없으면 `image:null` |

이미지 요청 본문은 `Content-Type: text/plain`의 `data:image/(png|jpeg|webp);base64,...` 문자열이다. 폰 화면은 긴 변 최대 1600px, JPEG 품질 0.85로 변환해 보낸다.

- 본문 상한: 8MiB(8 × 1024 × 1024바이트). 초과하면 `413 BAD_IMAGE`.
- 형식 불일치·본문 읽기 실패: `400 BAD_IMAGE`.
- 방별 대기 사진 20장에 도달하면 추가 전송은 `429 QUEUE_FULL`.

폰 화면은 촬영하거나 갤러리에서 고른 사진을 바로 보내지 않고, 줄인 사진을 브라우저 메모리에 최대 5장까지 담아 화면에 보여 준다. 담긴 사진과 합쳐 5장을 넘게 고르면 하나도 담지 않고 토스트("전송할 수 있는 이미지는 최대 5장입니다.")로 안내한다. 읽지 못한 사진은 담지 않고 안내하며, 5장이 차면 촬영·선택 버튼을 막는다. 사용자는 사진마다 × 버튼으로 삭제할 수 있다. **PC로 전송**을 누르면 담긴 순서대로 한 장씩 같은 전송 API를 호출하고, 보낸 사진은 화면에서 뺀다. 전송 오류가 나면 거기서 멈추고 보내지 못한 사진은 화면에 남겨 다시 보낼 수 있게 한다. 5장 제한은 폰 화면의 규칙이며 서버 제한은 아래 대기 20장뿐이다.

PC는 2초마다 같은 방을 조회하고, 사진이 있으면 서버 대기가 0이 될 때까지 이어서 가져온다. 01 탭에서는 확인 중인 영수증이 있어도 모두 가져와 브라우저 메모리의 대기 사진 목록에 넣고 화면에 표시한다. 미리보기가 비면 대기 목록의 앞 사진부터 한 장씩 올리며, 사용자는 대기 사진을 개별로 제거할 수 있다. PC 01 탭에서 선택·드롭·붙여넣기한 파일은 장수와 관계없이 서버를 거치지 않고 같은 대기 사진 목록 뒤에 넣는다. 확인 중인 영수증은 바꾸지 않는다. 대기 사진은 새로고침하면 사라진다. 02 탭에서는 출력 사진 준비가 끝났을 때 다음 사진을 가져오고, 준비 중이면 한 장을 PC 메모리에 들고 기다린다. 받은 시점에 열려 있는 탭을 기준으로 전달한다. 서버는 응답할 사진을 큐에서 즉시 제거한다. 탭 전환으로 방을 새로 발급하지 않는다.

### 만료와 보관

- 방은 활동 여부와 관계없이 생성 후 30분에 만료된다.
- PC가 만료 응답을 받으면 새 방을 만든다. 폰은 새 QR을 스캔해야 한다. **새 코드 받기**로도 방을 교체할 수 있다.
- PC 화면을 새로고침하거나 닫으면 `pagehide`에서 `DELETE /api/rooms/:code`(keepalive)로 방을 닫고, 다시 열린 화면은 새 방을 만든다. 브라우저 강제 종료 등으로 요청이 나가지 못하면 방은 30분 만료까지 남는다.
- 폰 화면은 주기적으로 조회하지 않는다. 촬영·선택 버튼을 누를 때와 사진을 전송할 때 `404`를 받으면 촬영 버튼을 숨기고 QR을 다시 찍도록 안내한다. 버튼을 누를 때는 조회 결과를 본 뒤 카메라·갤러리를 열며, 방이 닫혔으면 열지 않는다. 조회가 1.5초 안에 끝나지 않거나 통신 오류가 나면 방이 열려 있다고 보고 진행한다.
- 닫힌 코드는 6시간 재사용하지 않는다. 서버 재시작 시 기록은 사라지지만 새 키가 발급되므로 이전 QR은 사용할 수 없다.
- 요청 횟수 제한은 없다. 공개 배포 전 사용자 인증·접근 제한을 별도로 정한다.
- 이미지는 브라우저와 서버 메모리에만 둔다. 서버 큐는 사진 전달·방 만료 시 삭제하며, 폰에는 전송 전 담아 둔 사진만 화면을 닫거나 새로고침할 때까지 메모리에 남고, 전송한 사진은 화면에서 사라진다. 이미지는 디스크·로그·브라우저 저장소에 저장하지 않는다.

## 영수증 출력

01에서 수신·준비한 마스킹 전 이미지(기존 1600px 축소 적용)를 출력 목록에도 등록한다. 02 파일·QR 입력은 출력 전용이다. 자르기·회전·순서·배치 옵션은 브라우저 메모리에서만 처리하며 추출 요청과 결과에는 영향을 주지 않는다. 출력용 API는 추가하지 않는다.

## 결과 편집과 엑셀 복사

`account`, `description`, `payment`, `project`, `section`은 사용자 편집용 선택 필드다. `section`은 `dept` 또는 `project`이며 생략하면 부서경비로 처리한다.

- `account`: 경비 구분별 계정과목 목록에서 선택.
- `payment`: 결제수단 목록에서 선택.
- `description`, `project`: 직접 입력.
- 목록은 `frontend/src/constants/accounts.ts`에서 관리하며 시트와 연동하지 않는다.
- 추출 직후 거래처 이름으로 기본값을 채운다. 병원·의원·진료과는 의료비, 약국은 계정과목 의료비와 상세내역 약제비, 식당으로 식별되는 이름은 야근(특근)식비를 선택한다. 부서경비 결제수단은 개인카드를 기본으로 한다. 기본값은 편집할 수 있다.

일자·거래처가 있고 금액이 0보다 큰 정수여야 목록 추가·복사가 가능하다. 현재 검증은 날짜 형식·실제 날짜 유효성이나 시트 드롭다운 허용값까지 검사하지 않는다. 목록 상한은 없으며 경비 구분별 15행 초과 시 경고한다.

### 복사 배치

복사 단위는 경비 구분별 목록 전체다. 행은 개행, 열은 탭으로 구분한다.

| 방식 | 열 배치 |
| :-- | :-- |
| 6열 | 일자 / 계정과목 / 비용 상세내역 / 거래처 / 금액 / 결제수단(프로젝트경비는 프로젝트번호) |
| 원본 양식용 | B~X의 23열 중 B/D/G/P/S/V에만 값 배치 |

머리글·NO·합계·엔진·경고는 제외한다. 텍스트 금액에는 쉼표·원 표시를 넣지 않는다. 문자열의 탭·개행은 공백으로 바꾸고, 공백 뒤 `=`, `+`, `@`, `-`로 시작하는 값에는 작은따옴표를 붙인다.

### HTML과 수동 복사

두 방식 모두 `text/plain`과 구글 시트용 `text/html`을 함께 복사한다. HTML은 `<google-sheets-html-origin>`, `data-sheets-value`, `data-sheets-numberformat`을 사용한다.

원본 양식용 HTML에는 다음 서식을 넣는다.

- 병합 폭: `colspan 2/3/9/3/3/3`.
- 글꼴·테두리: Arial 9pt, 검은 가는 테두리.
- 정렬: 일자·계정과목·거래처 가운데, 상세내역·마지막 열 왼쪽, 금액 오른쪽. 상세내역은 줄바꿈 허용.
- 일자: 날짜 일련번호와 `yyyy. M. d` 형식. 금액: 숫자와 `#,##0;-#,##0` 형식.

Clipboard API가 실패하거나 없으면 `copy` 이벤트와 `execCommand`로 재시도한다. 모두 실패하면 수동 복사용 텍스트를 제공한다. 수동 복사에는 HTML 병합·서식이 포함되지 않는다.

원본 양식은 부서경비 22~36행, 프로젝트경비 46~60행 중 첫 빈 행의 B열에서 Ctrl+V로 붙여넣는다. 병합·서식 호환성은 실제 양식 사본에서 확인해야 한다. 시트 API로 직접 쓰지는 않는다.
