## 1. 기술 스택 및 현재 시제품 범위

- 처음에는 서버 구축·운영 부담을 줄이기 위해 Apps Script를 선택했다.
- 시제품 범위가 **영수증 OCR 결과를 웹 화면에 보여주는 것**까지로 축소되었다.
- 이에 팀원들이 익숙한 **React + Node.js로 전환하자는 제안이 나온 상태**다. 전환 방향을 기준으로 준비하되, 제안의 최종 확정 여부는 팀에서 확인한다.

| 영역 | 현재 방향 |
| :-- | :-- |
| 프런트엔드 | React + TypeScript 기본 프로젝트 |
| 백엔드 | Node.js 전환 제안 |
| 시제품 범위 | 영수증 입력 → OCR 추출 → 웹 화면에 결과 표시 |
| 이번 시제품 제외 | Google 시트 연결·쓰기, 승인 메일 발송, 결재 처리 |
| 통신·배포 | 프런트엔드와 백엔드 연결 규칙 및 배포 방식은 별도 정의 |
| 협업 | 회사 GitLab, 기본 브랜치 `main`, 각자 기능 브랜치에서 작업 후 팀원 1명 리뷰를 거쳐 병합 |

### 1.1 진행 준비 — 담당별 작업 전에 수행

1. 저장소를 생성하고 팀원을 초대한다. 기본 브랜치는 `main`으로 설정한다.
2. 각자 기능 브랜치에서 작업하고, 팀원 1명의 리뷰 후 병합한다.
3. React + TypeScript 기본 프로젝트는 한 번만 생성해 공유한다. 팀원 모두 같은 설치·실행 명령을 사용하며, 해당 명령을 문서화한다.
4. 아래 구조로 폴더를 구분한다.

```text
frontend/  # React + TypeScript 화면
backend/   # Node.js 백엔드 (전환 제안 기준)
docs/      # 프런트엔드·백엔드 연결 규칙 및 AI 활용 기록
```

> 전달된 준비안의 `backend/` 설명에는 Apps Script가 남아 있었으나, React + Node.js 전환 방향에 맞춰 Node.js로 정리했다. 최종 스택 확정 시 함께 확인한다.

### 1.2 기존 규칙의 적용 범위

- 아래의 개인정보 보호, 무료 범위 사용, Git 협업, AI 활용 기록 원칙은 계속 적용한다.
- **3~4장은 이전 Apps Script·시트 연동 설계의 참고 기록**이다. 현재 시제품의 구현 요구사항으로 적용하지 않는다.
- 2·5~8·11~13장에 남은 시트·메일·Apps Script 관련 세부 규칙 역시 향후 확장 참고이며, 현재 시제품에 적용하지 않는다.
- Apps Script 전용 `google.script.run`, User Properties, `clasp`, HTML 단일 파일 빌드 및 Apps Script에서의 React 실행 검증(C-04)은 현재 준비 작업의 요구사항에서 제외한다.
- Node.js의 API 계약, OCR 엔진 연결·대체 방식, 키 관리, 인증, 배포 방식은 별도 결정한다. 과거 Apps Script 설계를 그대로 옮기거나 미결정 사항을 임의로 확정하지 않는다.

## 2. 절대 원칙 (위반 시 리뷰 반려)

1. 비용 0원 — 유료 API/서버/DB 도입 금지. 무료 등급·Workspace 범위 안에서만 해결.
2. 양식 존중 — 지결 시트의 값 칸만 쓴다. 수식·집계·결재란·기본정보는 절대 건드리지 않는다.
3. 데이터는 사용자 소유 — 지결 데이터는 본인 시트에만 남긴다. 원본 영수증 이미지는 보관하지 않는다.
4. 사람이 최종 확인 — AI 추출 결과는 사용자가 화면 표에서 확인하기 전까지 시트에 쓰지 않는다.
5. 개인정보 최소 전송 — 외부 AI(Gemini)로 보내는 이미지는 가린(마스킹) 것만 보낸다.

## 5. 프런트엔드 (React + TypeScript) 규칙

- 공통 React + TypeScript 기본 프로젝트와 문서화한 설치·실행 명령을 사용한다.
- 현재 화면은 영수증 OCR 결과 표시에 집중한다. 백엔드 연결 규칙은 `docs/`에 정의한다.
- 아래 월 탭 재현 및 드롭다운 규칙은 향후 시트 연동 참고다.
- 작업 화면(S-01) 표는 "월 탭과 똑같은 모양" 으로: 열 머리(A~X)·행 번호(1~61)·병합·색을 원본과 일치.
  - 부서: 분홍 #D5A6BD / 자주 #A64D79 · 프로젝트: 하늘 #9FC5E8 / 파랑 #3D85C6 · 결재 머리: 노랑 #FFE599
  - 시트 기존 행 = 회색·잠김 / 추가할 행 = 왼쪽 파란 줄
  - '앱·상태' 열(시트에 없음)에 추출 엔진·영수증 보기·옮기기·삭제
  - 모바일은 가로 스크롤(행 번호 고정)
- 드롭다운은 *원본과 같은 출처*에서 받는다(5.1 "드롭다운 출처"). 값 하드코딩 금지.
- 브라우저 스토리지(localStorage/sessionStorage) 사용 금지 — 반영 전 데이터는 메모리(React state)에만.
- 영수증은 업로드 시 긴 변 1600px로 축소 후 처리.

## 6. AI / OCR 규칙 (7장)

- 기본: Gemini API 무료 등급 + 사용자 본인 키. 응답은 JSON 형식으로만.
- 대체: Drive OCR + 규칙 추출 (키 불필요, Workspace 밖으로 안 나감). Gemini 실패/한도 초과 시 전환하고 사용 엔진을 화면에 표시.
- 추출 항목: 일자, 거래처(영수증 상호명), 합계, 공급가액, 부가세, 승인번호, 품목, 필드별 신뢰도.
- 계정과목은 프롬프트에 체크 탭 목록을 넣어 그 목록 안에서만 고르게 한다.
- 읽을 수 없는 값은 비워 둔다 — 추측 금지. 금액은 원 단위 정수, 날짜는 YYYY-MM-DD.
- 가린 이미지만 전송, 개발·시연은 마스킹 샘플만 사용.

## 13. 공통 체크리스트 (PR/MR 전)

- [ ] 공통 설치·실행 명령으로 프로젝트를 실행했다.
- [ ] 현재 시제품 범위인 영수증 OCR 결과 화면 표시를 확인했다.
- [ ] 연결 규칙과 AI 활용 기록을 `docs/`에 반영했다.
- [ ] 기능 브랜치에서 작업하고 팀원 1명의 리뷰를 받았다.

아래 시트 관련 항목은 향후 시트 연동을 구현할 때만 적용한다.

- [ ] 시트의 수식/결재란/집계/기본정보 칸을 건드리지 않았다 (값 칸만).
- [ ] 병합 칸은 첫 셀에만, 일자는 날짜 값, 쓰기는 USER_ENTERED.
- [ ] 위치를 *머리글 탐지*로 구했다(좌표 하드코딩 폴백만).
- [ ] API 키·시트 주소·개인정보가 코드/로그/Git에 들어가지 않았다.
- [ ] 외부 AI로는 가린 이미지만, 원본 미보관.
- [ ] 무료 범위 안에서 해결했다(유료 의존성 없음).
- [ ] 미결정 사항을 *임의로 확정하지 않았다*(필요 시 PM 확인).
- [ ] AI 활용 *한 줄 기록*을 남겼다.
