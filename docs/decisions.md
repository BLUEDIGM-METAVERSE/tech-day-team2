# 결정 사항과 검토 항목

## 개발 기준

React + TypeScript(Vite), Node.js 내장 HTTP 서버, npm workspaces를 사용한다. OCR API는 기본 샘플 모드와 서버 환경변수로 선택하는 Gemini 모드를 제공한다.

## 2026-11-02 구현 사항

### 결과 목록과 선택 항목

- 확인한 결과를 메모리 목록에 쌓고 경비 구분별로 한 번에 복사한다.
- 새 행은 일자순 위치에 삽입한다. 기존 순서는 유지하며 ▲▼로 바꿀 수 있다.
- 목록 상한은 없다. 원본 양식의 경비 구분별 15행을 넘으면 경고한다.
- 팀 제공 목록을 `frontend/src/constants/accounts.ts`에 둔다. 계정과목은 부서경비 14개·프로젝트경비 6개, 결제수단은 법인카드·개인카드·현금영수증이다. 프로젝트번호는 직접 입력한다.

### 원본 양식 확인 기록

기존 기록상 양식 사본에서 확인한 내용이다. 이번 문서 검토에서는 사본을 다시 확인하지 않았다.

- 상세 행 병합: B:C / D:F / G:O / P:R / S:U / V:X.
- 서식: Arial 9pt, 검은 가는 테두리, 일자 `yyyy. M. d`, 금액 `#,##0;-#,##0`.
- 계정과목·결제수단 목록은 코드 상수와 일치한다.
- 일자는 해당 월 날짜 목록만 허용하므로 다른 달 일자는 시트에서 경고한다.
- 프로젝트번호는 월 탭 E41:E43에서 고른 값만 허용한다.

시트 주소·파일명은 저장소에 기록하지 않는다. HTML 복사에는 위 병합·서식을 반영했으며, 실제 붙여넣기 호환성은 양식 사본으로 확인한다.

### 폰 → PC 사진 전달

- QR로 연결한 폰에서 사진을 보내면 서버 메모리 큐를 거쳐 PC에서 받는다.
- 방은 생성 후 30분 또는 활동 없이 10분이면 만료된다. PC 조회도 활동에 포함된다.
- 6자리 코드는 표시용이다. 방 접근에는 QR 주소에 포함된 키를 사용한다. 사용자 인증은 별도로 구현하지 않았다.
- 닫힌 코드는 6시간 재발급하지 않는다. 현재 요청 횟수 제한은 없다.
- 폰은 사진을 긴 변 최대 1600px, JPEG 품질 0.85로 변환한다.
- QR 표시용 `qrcode-generator`를 추가했다. 담당 1·3의 관련 변경 검토와 의존성 추가에 대한 팀 확인이 남아 있다.

API는 로컬 주소에 바인딩한다. 폰 접속에는 프런트의 LAN 실행이 필요하며, 팀의 LAN 테스트 허용 여부는 미결정이다. 기본 실행은 로컬 전용이다.

## 2026-11-03 구현 사항

### 서버 안정화와 연결 구조

담당 3의 독립 작업 범위다. 팀 합의가 필요한 OCR 입력·오류·타임아웃은 정하지 않았다.

- API를 `backend/src/app.mjs`로 분리하고 `server.mjs`는 포트 실행만 맡는다. 시험에서 임의 포트와 가짜 엔진을 쓰기 위해서다.
- 해석할 수 없는 주소, 글자 수가 같은 멀티바이트 `key` 요청 한 건으로 서버 프로세스가 종료되던 문제를 고쳤다. 처리 중 예외는 `500 INTERNAL_ERROR`로 응답한다.
- 프런트 서버 호출 오류를 `frontend/src/services/http.ts`로 모았다.

### 담당 4 검토가 필요한 제안

- 샘플과 실제 OCR의 연결 지점으로 `backend/src/ocr/engine.mjs`의 `{mode, extract()}` 형태를 제안한다. `extract()`의 이미지 입력은 합의 후 추가한다.
- `/api/extract` 클라이언트 시간 제한 30초는 샘플 API용 임시 값이다. 실제 OCR 타임아웃으로 간주하지 않는다.

## 2026-11-10 Gemini OCR 시제품

- 로컬 서버의 환경변수로 키와 모델을 설정하고 기본은 샘플 모드로 둔다. Gemini는 사전 마스킹한 로컬 PC 이미지에 연결했다.
- 모델 전사와 기존 규칙 파서를 분리하고 기본 세 필드와 경고를 사용한다. Gemini 오류는 샘플 응답으로 대체하지 않는다.
- 이미지 상한 8 MiB와 서버 20초·클라이언트 30초는 시제품 설정이다. 실제 호출 검증 뒤 재검토한다.

## 미결정 사항

- 실제 OCR 엔진·무료 사용 범위·실패 시 대체 경로.
- OCR API 키 관리, 사용자 인증·접근 제한, 배포 환경.
- 마스킹 대상·방식, 실제 OCR 이미지 전송 제한·형식·타임아웃.
- OCR 최종 JSON·추가 필드·신뢰도·업무 검증 정책.
- 목록 상한·초과 처리의 최종 정책, 목록·시트 연동 여부.

키는 로컬 백엔드 환경에서 설정한다. 공개 배포 전 인증·배포 정책을 정한다.

## 과거 시안 참고 범위

현재 규칙은 루트 `AGENTS.md`를 따른다. 과거 Apps Script 설계는 `docs/legacy/AGENTS-apps-script.md`에 보관한다.

### 폰 사진 여러 장 전송 (2026-11-12)

- 폰 갤러리 선택은 한 번에 최대 5장이다. 6장 이상은 보내지 않고 다시 선택하게 한다. 촬영은 한 장씩 유지한다.
- 01 탭의 PC는 서버 대기 사진을 모두 가져와 브라우저 메모리의 대기 사진으로 표시하고, 도착 순서대로 한 장씩 확인한다. 대기 사진은 개별 제거할 수 있고 새로고침하면 사라진다.
- 서버 API·방별 대기 20장·30분 만료는 바꾸지 않았다. PC 대기 사진 수 상한과 대기 사진의 순서 선택은 두지 않았으며 필요하면 따로 정한다.
- 검증: check/build, 프런트 테스트 39개, 백엔드 테스트 68개 통과. 실제 휴대폰 갤러리 다중 선택과 브라우저 화면 동작(대기 사진 표시·자동 넘김·제거)은 미검증이다. 담당 1·3 검토가 남아 있다.

### 폰 전송 전 확인과 방 닫기 (2026-11-12)

- 위 "갤러리 선택은 한 번에 최대 5장, 촬영은 한 장씩 즉시 전송"을 바꿨다. 폰은 촬영·선택한 사진을 화면에 최대 5장까지 담고, × 버튼으로 삭제하거나 **PC로 전송**으로 보낸다. 담긴 사진과 합쳐 5장을 넘게 고르면 일부만 담지 않고 전부 담지 않으며 토스트로 안내한다.

### 중복 내역 경고 (2026-11-12)

- 사진 단계에서는 중복을 거르지 않는다. 목록 단계에서 일자·금액·거래처가 모두 같으면 중복 의심으로 본다. 부서경비·프로젝트경비를 통틀어 비교한다.
- 거래처는 전각·반각, 대소문자, 공백·괄호·기호, `(주)`·`㈜`·`주식회사` 표기를 무시하고 비교한다. 정리한 이름의 한쪽이 다른 쪽을 포함해도 같은 거래처로 본다(`KJFOOD`와 `[영수증] KJFOOD`). 한 글자 이름은 완전히 같을 때만 인정한다. 계정과목·상세내역·결제수단·프로젝트번호는 사용자가 고르는 값이라 비교하지 않는다.
- 같은 가게·같은 날·같은 금액의 정상 건이 있으므로 차단하지 않는다. 추출 결과 카드에 경고와 `그래도 목록에 추가`를 보여 주고, 목록에서는 해당 행을 노란색으로 표시하며 복사는 허용한다.
- 승인번호·거래 시각이 OCR 결과에 없어 재촬영 시 거래처가 크게 다르게 읽히면 놓칠 수 있다. 필드 추가는 OCR 결과 계약 변경이므로 따로 정한다.
- 검증: check/build, 프런트 테스트 45개, 백엔드 테스트 68개 통과. 브라우저 화면 동작은 미검증이다. 담당 2 검토가 남아 있다.
