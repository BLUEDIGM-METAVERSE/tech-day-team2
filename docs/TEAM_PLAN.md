# 4인 개발 업무 종합

## 공동 목표

영수증 입력 → 실제 OCR → 지출결의서 형식으로 확인·수정 → 엑셀 복사.
현재 업로드·미리보기·가짜 API·단일 결과 편집·엑셀 복사는 구현되어 있다. 실제 OCR·마스킹 편집·인증·배포는 아직 구현되지 않았다. 아래 TODO의 체크는 담당자가 직접 검증한 뒤 완료한다.

작업 전 [AGENTS.md](../AGENTS.md), [README.md](../README.md), [연결 규칙](connection.md), [결정 사항](decisions.md)을 읽는다.

## 병렬 개발과 통합 순서

1. **현재 기반 확인:** 전원 `npm ci`, `npm run dev`, `npm run check`, `npm run build`를 수행하고 샘플 흐름을 확인한다.
2. **독립 작업:** 담당 1은 파일 처리, 담당 2는 가짜 결과 편집·복사, 담당 3은 API 검증, 담당 4는 마스킹 샘플 OCR 실험을 진행한다.
3. **계약 합의:** 이미지 전달 형식·허용 크기·제한·오류·OCR 응답을 담당 1·3·4가 맞추고 담당 2가 화면 영향을 확인한다.
4. **실제 연결:** 담당 4의 모듈을 담당 3이 서버에 연결하고 담당 1이 처리한 이미지를 전달한다. 마스킹 정책과 외부 전송 조건을 충족하기 전까지 미리 마스킹한 샘플만 사용한다.
5. **전체 확인:** 실제 OCR 결과를 담당 2의 표에서 수정하고 Excel 양식 사본에 복사해 확인한다.

OCR 결정이 지연되어도 업로드·결과 화면·가짜 API 검증은 계속한다. 실제 OCR 미연결 상태를 완료로 표시하지 않는다.

## 공동 결정이 필요한 항목

| 항목 | 논의 주도 | 결정 전 진행 방식 |
| :-- | :-- | :-- |
| OCR 엔진·무료 범위·대체 경로 | 담당 4·3 | 마스킹 샘플 실험·가짜 응답 |
| 이미지 전송 형식·용량·타임아웃·오류 | 담당 3·1·4 | 현재 무본문 가짜 API 유지 |
| 마스킹 대상·방식·확인 절차 | 담당 1·4, 전원 검토 | 미리 마스킹한 샘플 사용 |
| 키 관리·인증·배포 | 담당 3, 전원 검토 | 로컬 개발만 진행 |
| 추가 추출 필드·신뢰도·목록·다중 영수증 | 담당 2·4, 전원 검토 | 현재 단일 행·기본 필드 유지 |

합의 결과는 `docs/decisions.md`, 계약 변경은 `docs/connection.md`에 기록한다. 미결정 기능을 각자 다른 방식으로 구현하지 않는다.

## 충돌 방지와 리뷰

- 기능 브랜치 예시: `feature/upload`, `feature/result-excel`, `feature/server`, `feature/ocr`.
- `App.tsx`, `types/receipt.ts`, `styles.css`, 패키지·설정 파일은 공통 파일이다. 변경 범위를 관련 담당과 조율하고 PR/MR에 영향을 설명한다.
- 권장 리뷰 짝: 담당 1 ↔ 담당 2, 담당 3 ↔ 담당 4. 공통 계약 변경은 영향을 받는 담당이 검토한다.
- 팀원 1명 리뷰 후 `main`에 병합한다. 다른 AI가 작성한 코드도 담당 개발자가 직접 검토한다.
- 각 AI에는 공통 문서와 자신의 TODO를 읽고 작업하도록 지시한다. AI 활용 기록은 `docs/ai-usage.md`에 남긴다.
